TINY 2 training kit
===================
facts/*.txt     one-off facts:  question | question | ... => answer | answer
facts/*.tsv     table facts:    relation <TAB> subject <TAB> answer
raw/            hand-written word lists that were turned into facts/words2.tsv
gen2.py         turns the facts into endless question/answer pairs
                (phrasings, reverse, yes/no, two-part, numbers, letters,
                "I do not know", typos).  python3 gen2.py shows samples.
train2.py       PyTorch training, evaluation and export to TINY.BIN
geo2.py, extra_facts.py   rebuild geography/element tables from the public
                mledoze/countries and Periodic-Table-JSON datasets (GitHub)
tiny2.pt        the trained network (same as TINY.BIN, full precision)
export_onnx.py  converts the network to ONNX and runs it with onnxruntime
                (reads dos/TINY.BIN directly, no PyTorch needed)

Continue training and export (needs Python 3 and PyTorch, CPU is fine):
  python3 train2.py train 60 more.pt --resume tiny2.pt --lr 5e-4 --decay 0.3 --eval-every 20
  python3 train2.py eval more.pt
  python3 train2.py export more.pt TINY.BIN
The same TINY.EXE reads the new TINY.BIN.

Run it on a modern machine (ONNX, needs numpy, onnx and onnxruntime):
  python -m venv .venv && .venv/bin/pip install numpy onnx onnxruntime
  python export_onnx.py export ../dos/TINY.BIN tiny2.onnx
  python export_onnx.py ask tiny2.onnx "what is the capital of peru"
  python export_onnx.py selftest ../dos/TINY.BIN tiny2.onnx
The graph takes letter ids [batch, seq] and gives logits [batch, seq, 97];
export_onnx.py ask does the letter-by-letter decoding.

  python export_onnx.py export-step ../dos/TINY.BIN tiny2_step.onnx
One letter per call, with the key/value memory passed in and out, all shapes
fixed: the form a C code generator wants (see cgen/).

Add --int8 to either export to keep the weights as the 8-bit values they are
stored as, with one DequantizeLinear per table (one scale per row, as in
TINY.BIN). The arithmetic stays float32 and the answers do not change; the
model file goes from 1.5 MB to 0.4 MB.

quantize_int8.py goes further and quantizes the activations as well, so the
matmuls become integer operators (QLinearMatMul). That needs calibration,
which it does by running the float model over real questions from gen2.py:
  python quantize_int8.py calibrate ../dos/TINY.BIN tiny2_step.onnx out.onnx \
      "--keep-float=logits,*scores,*ctx" --per-tensor
  python quantize_int8.py compare tiny2_step.onnx out.onnx ../dos/TINY.BIN
It also has a dynamic mode, which needs no calibration at all and keeps the
per-row weight scales:
  python quantize_int8.py dynamic tiny2_step.onnx tiny2_step_dq8.onnx
Unlike the weight-only export, quantized activations change the answers:
97% of them stay literally the same with the dynamic mode, 67-85% with the
static one. cgen/README.md has the numbers and the reasons.

How TINY 2 was trained: started from the version 1 network (grown from 3 to
4 layers, middle layer 192 -> 256), 20 minutes on the first new data set,
15 minutes more, then 150 minutes and another 180 minutes on the full data
set (about 15 million examples in all), on 2 CPU cores.
Score on 780 unseen test questions: 61% (version 1: 6%).
